# Контроль Альбома ТФФ ЕИС

Версия комплекта **0.1.6**. Прикладного сервера нет: инструмент состоит из статической HTML-страницы, локальных библиотек и расширения-моста Manifest V3.

## Первый запуск

1. Распакуйте комплект в постоянную папку.
2. Отключите или удалите предыдущий мост, затем загрузите расширение из этого комплекта. Версия страницы и расширения должна быть 0.1.6.
3. Откройте страницу расширений браузера, включите режим разработчика и выберите «Загрузить распакованное расширение».
4. Укажите папку `extension` из этого комплекта.
5. Для отдельного локального запуска включите расширению доступ к URL файлов и откройте `index.html` двойным щелчком. В шапке должно появиться «Расширение-мост — Подключено».
6. Сначала проверьте ручной режим на двух известных архивах. Для альбомов 16.2.4 и 16.2.6.9 контрольный результат: 2 изменённых файла, 17 без изменений, остальные счётчики — 0.

Ручной режим A/B работает и без расширения. Все документы обрабатываются в памяти браузера.

## Проверка ЕИС

1. Выберите период и нажмите «Проверить источник».
2. Мост начинает с первой страницы раздела 432 и прекращает обход, как только найдены все публикации внутри периода и предшествующая базовая версия. Для периода 01.08.2026–20.08.2026 достаточно первой страницы; остальные пять не запрашиваются.
3. Страница предлагает соседнюю пару: последнюю публикацию внутри периода и непосредственно предшествующую ей версию. База может находиться до начала периода — это нормальное поведение.
4. При необходимости назначьте другие публикации переключателями «Старая» и «Новая».
5. Нажмите «Сравнить выбранные». Оба ZIP расширение загрузит само; сохранять их на диск и затем загружать вручную не нужно.
6. После сравнения можно выгрузить отчёт для Word или единый комплект со старым ZIP, новым ZIP, отчётом и `summary.json`.

В списке остаются публикации внутри выбранного периода и одна предыдущая базовая версия. Если внутри периода ничего нового нет, показываются две ближайшие предыдущие версии для ручного сравнения.

## Просмотр исправлений

После сравнения над перечнем файлов появляются две команды.

- **Показать только исправленное** — раскрывает все изменённые файлы и оставляет внутри diff только красные удалённые и зелёные добавленные фрагменты. Неизменённые участки заменяются разделителем.
- **Перейти к исправлениям** — открывает полную ленту и переводит по исправлениям только в тех изменённых документах, которые сейчас раскрыты. Свёрнутые документы исключаются из счётчика и навигации. Если ни один изменённый документ не раскрыт, команда раскрывает первый.

Переключатель **«Показать все 19 документов»** добавляет в ленту неизменённые файлы. Их можно раскрыть и прочитать; изменённые, добавленные и отсутствующие документы выделены цветом. Кнопка **«Показать только документы с изменениями»** возвращает компактный список.

Повторное сравнение не запускается. Краткий отчёт для Word не копирует полные документы: в нём есть сводка, кликабельный перечень изменённых файлов и отдельные блоки «Было» / «Стало» только для исправленных фрагментов.

## Загрузка архивов

Во время автоматической загрузки каждого пакета показываются этап, процент, получено и осталось байт, прошедшее время и расчётное оставшееся время. Если сервер не сообщает общий размер, отображаются полученные байты и прошедшее время без выдуманного процента.

Имя архива из `Content-Disposition` восстанавливается для распространённых ошибочных вариантов UTF-8 и Windows-1251. Если заголовок всё равно неоднозначен, используется понятное имя публикации, а не битая строка.

## Что сравнивается

- состав пакетов относительно общей корневой папки;
- файлы, которых нет в новом комплекте — отдельной красной группой в начале результата;
- добавленные, изменённые и однозначно переименованные файлы;
- SHA-256 каждого элемента;
- содержимое TXT, XML/XSD, JSON, CSV, DOCX, XLS/XLSX, PPTX и PDF;
- формулы Excel, если они сохранены в файле и доступны библиотеке;
- кодировки UTF-8, Windows-1251, CP866 и KOI8-R по строгой проверке и эвристике.

Точное переименование определяется только при единственном старом и единственном новом пути с данным SHA-256. При неоднозначности показываются отдельные «нет в новом» и «добавлен», а не придуманная связь.

## Встраивание обычным `iframe src`

Страница не требует серверной логики, но браузер всё равно должен получить её по адресу, допустимому внутри Эталона.

- Для отдельного запуска можно использовать `file://`.
- В HTTPS-Эталон нельзя встроить `file://` и нельзя встроить обычный `http://`: браузер заблокирует локальный ресурс или mixed content.
- Для рабочего `iframe src` папку `index.html`, `app.js`, `styles.css` и `vendor` нужно целиком разместить на доступном статическом HTTPS-адресе. Это может быть штатное статическое размещение; backend приложения не нужен.

## Безопасность моста

- Источник ограничен точным публичным списком документов ЕИС: `https://zakupki.gov.ru/epz/main/public/document/view.html`, раздел 432.
- Загрузка разрешена только из `/epz/main/public/` на HTTPS-домене `zakupki.gov.ru`.
- ZIP загружается внутри фоновой вкладки публичного раздела ЕИС. Это использует тот же браузерный контекст, в котором список уже открылся, и устраняет `Failed to fetch` служебного процесса расширения.
- Адрес ZIP не приходит от страницы инструмента: расширение берёт его только из выбранной публикации текущей capability-сессии.
- После поиска страница получает временные идентификаторы сессии и публикаций. Передать расширению произвольный URL для скачивания больше нельзя.
- Сессия привязана к конкретной вкладке и iframe, живёт 10 минут и хранится в `chrome.storage.session`.
- Архив проверяется по ZIP-сигнатуре, CRC32 и лимитам до передачи в сравнение.
- Переадресованный ответ принимается только если конечный адрес остаётся в публичном разделе ЕИС.

Разрешения расширения: `scripting` для чтения фоновой вкладки и `storage` для короткоживущих capability-сессий. `tabs` не требуется.

Пока точный HTTPS-адрес инструмента в Эталоне неизвестен, content script объявлен для `file`, `http` и `https`. После размещения `matches` в `extension/manifest.json` желательно сузить до реального адреса инструмента.

## TLS и сертификат ЕИС

Расширение не отключает проверку сертификата браузером. Начиная с версии 0.1.4 ZIP скачивается в уже открываемой фоновой вкладке ЕИС, поэтому отдельный служебный `fetch`, который падал в 0.1.3, больше не используется. Если сам браузер не открывает ЕИС из-за сертификата, нужно один раз открыть zakupki.gov.ru в этом же профиле и подтвердить сертификат по правилам организации.

## Ограничения

- Автоматический разбор fail-closed: если разметка, порядок дат, версия или ссылка неоднозначны, ранняя остановка не применяется; мост продолжает постраничную проверку или выводит конкретную ошибку.
- До 10 страниц по 100 документов, до 200 публикаций основной серии, до 120 МБ на ZIP, до 2500 файлов и до 300 МБ после распаковки.
- Содержательный diff одного файла ограничен 25 МБ; более крупный поддерживаемый файл фиксируется по SHA-256.
- Изменение стилей, метаданных или внутренней структуры Office-файла может не проявиться в извлечённом тексте. В таком случае интерфейс прямо сообщает, что SHA различается, а извлечённый текст совпадает.
- Для настоящего iframe требуется отдельная приёмка в целевом HTTPS-контуре Эталона и под целевой ролью.

Подробная доказательная база и границы проверки находятся в `ПРОВЕРКА.md`.
